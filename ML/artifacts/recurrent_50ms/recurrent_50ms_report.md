# 旧方式（今回の指定により廃止）

このレポートは「3フレーム先予測を3フレーム後に再投入する」旧実験です。今回指定された「1フレーム先を逐次予測して指定時間までrolloutする」結果は `../autoregressive_horizons/autoregressive_report.md` を参照してください。

## 毎フレーム50ms先・再帰予測実験

各フレームで3フレーム（約50ms）先を予測します。連鎖条件では系列先頭の3フレームだけを実入力で初期化し、それ以降は3フレーム前に当該フレーム向けに出した予測行動を現在行動として、XGBoost/FEPを毎フレーム再実行しました。

今回の入力ログはオフライン対戦であり、実際のpacket arrival時刻はありません。そのため連鎖条件は『50ms後も実入力が復帰せず、そのまま未着が続く』保守的なシミュレーションです。位置・速度などはログ上のローカル状態を用い、予測で置換・連鎖するのは5クラス行動、対応入力ビット、行動継続時間および行動履歴です。予測入力による物理状態そのものの再シミュレーションではありません。

## 実行動変化の有無

『変化あり』は予測元フレームの実行動クラスと50ms後の正解クラスが異なるケースです。モデル入力に予測行動を使ったかどうかでは分けていません。

## 所見

連鎖条件のAccuracyはXGBoostが0.477（参照条件から0.402低下）、FEPが0.057（同0.500低下）でした。現在行動の予測誤りを次の入力へ無期限に引き継ぐと、両方式とも誤差が蓄積します。

XGBoostの連鎖条件は、実行動の変化ありで0.302、変化なしで0.513でした。行動が継続するケースでも参照条件ほど維持できず、復帰時の実入力による補正が重要です。

FEPの連鎖条件ではApproachが100.0%を占めました。予測を観測として再投入した結果、信念と方策が単一クラスへ自己強化的に収束しています。

## 解釈上の注意

連鎖条件は復帰時刻を固定せず、未着が継続する限界ケースです。オンラインログに `remote_input_confirmed` / `remote_input_predicted` と packet arrival が記録された場合は、同じ評価器へ実到着マスクを与える評価へ置き換えるのが次の段階です。ゲーム中の位置・速度・当たり判定まで予測行動で変化させた最終評価には、Unityのrollback/resimulation上で同じ推論器を実行する必要があります。
