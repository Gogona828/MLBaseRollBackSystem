# 再シミュレーション実施前の確認（2026-09-07）

現行 frames.csv から厳密な開始状態を復元できないため、正解入力の再現性・HP誤差の基準値は未取得。Python で近似した物理状態を正解ゲームの結果とは扱わない。

## 確認した不足

- Fighter の CaptureSnapshot が保持する currentActionHitCount、isInputBackward、isReserveProximityGuard、reserveDamageActionID、入力/押下/解放の履歴配列は frames.csv に揃っていない。
- BattleCore のラウンド時刻、記録/再生カーソル、KO確定待ち情報もCSVだけでは復元できない。
- RestoreSnapshot はボックス更新と押し合い処理も行う。復元直後に元スナップショットと一致するかを先に確認する必要がある。
- DoFixedUpdate は入力記録・ログ・時間など実行環境へ依存する処理を含む。通常試合に候補経路を適用すると、副作用まで生じる可能性があるため、評価専用の実行環境が必要。

## 必要な次の検証

1. 試合開始時の完全なスナップショット、ゲーム設定・アセット版、固定時間刻み、両者の確定入力を保存する。乱数を使う経路では乱数状態も保存する。
2. 評価専用のUnity実行環境で、ログなど外部への副作用を分離し、正解入力を再実行する。
3. 各フレームで完全な状態を比較。整数・入力・Action IDは完全一致、浮動小数点は評価前に絶対誤差許容幅を固定する。
4. 再現性を通過した区間に限って、入力継続・既存モデル・イベントモデルを同じ開始状態から比較する。

実入力は左右・攻撃のビット列を使う。5クラスからAttackの種類や押下/解放時刻を一意に復元できないため、現時点のイベントモデル出力は評価用の行動クラスであり、入力列モデルとしては未接続。

50/100/200msの状態更新付き行動列、FEP比較、複数経路、HP/ガード/位置・ヒット結果の評価、新規セッションの検証は未完了。既存ログの不足を推測値で埋めて実施済みとはしない。
